# 编译、烧录与分步验证

2026-10-21新增 **05_dual_sweep** Target与HEX，供两只舵机同时小幅往返检查接线，详见 [Keil直接烧录与往返测试](Keil双舵机往返测试.md)。下文01～04验证流程继续适用；第五个Target是独立手动测试选项，不是视觉闭环后的运行阶段。

工程根目录 `..`。先阅读 [供电与逐线连接说明](供电与逐线连接说明.md)。本次提供的是专用二维云台固件，会替代C30D原应用；不包含原来的ROS、电机驱动、IMU功能。

## 1. 先用已编译HEX，不必先建STM32工程

`outputs/firmware`下四组HEX/BIN已用本机 MDK Arm Compiler 6.7 编译链接通过；4阶段共用同一套源码和配置，每次只烧其中一个文件，不把四个文件拼接。

| 顺序 | 固件 | 行为/验收 |
|---|---|---|
| 1 | `01_yaw_center.hex` | 只PC6输出50Hz、1500μs；底座回中，PC7不输出PWM |
| 2 | `02_pitch_center.hex` | 只PC7输出50Hz、1500μs；俯仰回中，PC6不输出PWM |
| 3 | `03_uart_monitor.hex` | 接收PA3串口（USART2_RX/AF7），打印解码结果；两路均无PWM，测试时可关闭舵机电源并支撑俯仰 |
| 4 | `04_tracking.hex` | 两路回中后开始跟随；默认收到目标才改变指令角度 |

阶段1/2先单独接一只舵机，卸载或松开舵盘。1500μs约对应270°型号内部135°、180°型号内部90°。居中后断电、把舵盘安装到机构正前/水平。不要靠更改舵机“总行程”常量来矫正装歪。

## 2. 用ST-Link烧录：推荐的可复现路径

1. 安装 STM32CubeProgrammer 和 ST-Link 驱动，按接线说明接SWD。C30D由蓝色端子供电，ST-Link不带舵机供电。普通启动保持BOOT0为0，不改板上BOOT焊盘。
2. 打开CubeProgrammer，选ST-LINK、接口SWD、频率先400kHz，点击Connect，应识别STM32F407系列。
3. 如果需保留原厂应用，先读出/保存可读的Flash（本型号从 `0x08000000` 长度 `0x80000`）。若存在读保护，不要为备份而解除保护，解除可能擦除原程序。
4. 在文件烧录页面打开阶段1的HEX，点击Download/Start Programming并启用Verify。HEX自带Flash地址；用BIN时起始地址必须是 `0x08000000`。不要改Option Bytes或读保护。
5. 成功后复位/重新上电；打开串口1的CH9102 COM口，115200 8N1。每200ms应有阶段/脉宽日志。测波形可看到周期约20ms、高电平约1.5ms。
6. 完成当前阶段验收，再用相同方法替换下一阶段HEX。烧录前关舵机电源，阶段1/2首次上电先卸载；阶段4启动仍会回中。

若无法连接，先检查供电、共地、SWDIO/SWCLK，降低SWD频率；需要时接NRST用Connect under reset。只有实机连接后才能确认下载器和板子状态；本次没有代你实际烧录。

官方也支持“串口1一键下载”。这需要配套上位机按其DTR/RTS时序进入ROM bootloader；不能保证通用串口助手或CubeProgrammer自动完成。本文没有取得厂商下载软件的操作页，因此不编造按钮。使用厂商配套工具时，选择F407及本工程HEX并按其说明操作；不要把串口3当下载口。推荐先使用上面的SWD方法。

## 3. 单舵机小幅测试与重新编译

配置文件：`firmware/Core/Inc/pantilt_config.h`。阶段1/2默认只回中，没有自动扫到端点。回中正常后可将 `PT_TEST_PULSE_US` 从1500依次改为1450、1550，**每改一次重新编译烧录对应阶段**。编译检查限制在1400～1600μs，便于初期验证；测试后改回1500。

本机已有Keil MDK5、Arm Compiler6.7和Python，可直接在PowerShell运行：

```powershell
python ..\firmware\build_keil.py
# 只构建某个阶段
python ..\firmware\build_keil.py --stage 1
```

默认编译器目录 `C:\Keil_v5\ARM\ARMCLANG\bin`；其他电脑用 `--tools "你的ARMCLANG\bin目录"`。输出到 `outputs/firmware`，日志/AXF/map在 `work/build`。首次运行需已安装且授权可用的MDK Arm Compiler6，不会自动联网安装工具链。源码依赖已随工程提供。

也可双击 `firmware/C30D_PanTilt.uvprojx`，选择对应Target→Build（F7）。使用Arm Compiler6；本工程直接带CMSIS，不需RTE生成HAL。Keil界面生成文件在 `work/uvision/阶段名`，命令脚本生成文件在 `outputs/firmware`，避免混淆旧文件。Keil内下载需自行选择ST-Link/SWD并配置STM32F4 512KB Flash算法；本文首选CubeProgrammer烧录已有HEX。

## 4. 串口阶段：先不跑模型

PA3新版 `03_uart_monitor_PA3.hex`（与本次原名03固件内容相同）日志增加 `rx` 接收字节计数，未组成完整帧也计数；启动标识 `UART_RX_PA3_V3: USART2 RX=PA3 AF7`。`ok`持续为0时参阅 [串口零接收排查](串口零接收排查.md)。

1. C30D烧 `03_uart_monitor_PA3.hex`；电脑打开串口1日志COM。K230 TX IO44→C30D预留IO排针 PA3，GND→GND；K230原视觉程序暂停，避免UART2被占。K230的USB1接电脑IDE时按接线说明选择供电，不把电脑5V与外部5V直接并联。
2. 用CanMV IDE把 `k230/pantilt_uart.py` 与 `k230/uart_smoke_test.py` 保存到K230 `/sdcard/`，并确保该目录在sys.path中；在IDE打开并运行 `/sdcard/uart_smoke_test.py`。必要时在脚本导入前加 `import sys; sys.path.append('/sdcard')`。
3. 默认 `MODE="lost"`，20Hz发 `$T,0,0,0\n`；应看到 `ok`累加、found=0、ex=ey=0、bad与uart_err不增长。`MODE="center"` 发found=1居中帧。
4. `MODE="direction"` 只发一次0.5秒偏差突发，随后丢失帧及1秒静默后结束。默认AXIS=yaw、ERROR=150，监视阶段应看到ex=150；改pitch则ey=150。阶段3无PWM，pwm日志数值是内部初始值，不代表针脚输出。
5. 可用独立3.3V USB-TTL转接器TX→PA3、GND→GND测试文本；此时拔K230 TX，不能两路TX并接。发送必须是真正换行LF（可CRLF），不是字面两个字符反斜杠n。115200 8N1，无流控。

日志：`ok`有效帧数，`bad`拒绝行数，`uart_err`硬件串口错误，`age`最近有效帧距今毫秒（首帧前无意义），`active`跟随有效状态，`pwm`最后指令脉宽。坏帧不刷新超时；若uart_err增长，先核对电平、共地和波特率。本工程使用内部HSI16MHz，PWM/串口频率有内部时钟误差；温度变化较大或串口不稳时，测量后再按板实际晶振配置HSE，不猜晶振频率。

## 5. 方向和保持测试，再接视觉

烧 `04_tracking_PA3.hex`（与本次原名04固件相同，接收脚也改为PA3），机构先回中。运行K230小偏差direction测试，分别测两轴，不要持续发满量程误差：

- 目标误差ex>0代表在图像右边，正确动作是相机向目标右侧转；ey>0代表图像下方，相机应向下转。相机跟着云台转，因此正确动作会使偏差绝对值减小。
- 安装方向决定正反。根据当前实机左右反向的反馈，已将yaw sign从+1改为-1，pitch sign保持-1，并重新编译阶段4。若以后改变安装方向，只改配置的 `PT_YAW_SIGN` / `PT_PITCH_SIGN` 正负并重新编译阶段4。不要一边反转误差、一边反转sign。
- 有效帧found=0：下一个20ms控制周期停止改变指令角度；断开发送但保留共地/供电：最后有效帧300ms后停止改变指令角度。PWM继续维持最后指令；不是断电，也不是回中或自动搜寻。舵机可能仍在完成到该指令角度的机械运动，实际保持也受供电和负载影响。
- 只有格式正确、范围正确的完整帧才刷新通信时间。恢复found=1后从当前软件指令继续跟随；控制中不会积压一串旧动作，采用最新完整帧。

确认方向后再在已跑通的视觉循环调用发送。`person_detection_tracking.py`是此前修改过的本地人形例程副本：初始化UART2、每帧选面积最大的class0目标，用**原AI图像尺寸**算偏差，最多20Hz发送，检测丢失时立即发found=0，退出尽力发丢失帧。它保留person模型路径；并没有训练或替换成玩偶模型。已有玩偶模型请保留其推理，只接入下面的发送代码。

```python
from machine import UART, FPIOA
from pantilt_uart import setup_uart, send_detection, send_packet
import time
uart = setup_uart(UART, FPIOA())
last_send = time.ticks_ms()
# 在现有YOLO每帧得到results之后执行：
now = time.ticks_ms()
if results is None or len(results) == 0:
    send_packet(uart, False)  # 检测丢失时尽快通知
    last_send = now
elif time.ticks_diff(now, last_send) >= 50:
    send_detection(uart, results, image_width, image_height, target_class=0)
    last_send = now
# 程序退出时尽力send_packet(uart, False)，再uart.deinit()
```

这里要求results每项为 `[class_id,score,x1,y1,x2,y2]`，坐标已经从模型letterbox映射回原图；target_class改为玩偶类别编号。用原图/AI采集图像宽高，不用模型640×640代替640×480原图。第一次调试在IDE手动运行；通过后再按CanMV的开机脚本方式保存到板端main.py，避免一开机就未知方向运动。

## 6. 控制参数与代码各自作用

| 文件 | 作用 |
|---|---|
| `BSP/c30d_bsp_stm32f407.c` | F407寄存器、HSI16MHz、TIM3 PWM、USART2中断接收、USART1日志、1ms时基 |
| `Core/Src/pantilt_protocol.c` | 按字节收包、换行组帧、范围/长度检查、损坏后重新同步 |
| `Core/Src/pantilt_controller.c` | 误差→比例角速度→按时间积分角度，死区、角度限位、速度限幅、丢失/超时保持 |
| `Core/Src/pantilt_app.c` | 串口与控制器连接，保存最新完整帧及接收时间，中断/主循环间保护 |
| `Stages/servo_single_test.c` | 阶段1/2只开启一轴固定脉宽 |
| `Stages/uart_protocol_test.c` | 阶段3真实串口接收，关闭PWM |
| `Core/Src/main.c` | 选择阶段，20ms控制调度，每200ms日志 |
| `Core/Inc/pantilt_config.h` | 集中修改PWM标定、限位、方向、死区、增益、速度和超时 |
| `k230/pantilt_uart.py` | K230 UART2初始化、选择最大面积框、归一化偏差和发送 |

当前死区各±15（半幅的1.5%，全幅的0.75%）：640×480下约左右±4.8像素、上下±3.6像素，原先为±35。超出死区后，按扣掉死区的误差连续增加速度；满误差yaw60°/s、pitch21°/s，分别限速60°/s、25°/s。本次底座从35°/s提高到60°/s；例如ex=200时约11.3°/s，接近中心仍自动减速。这些是控制器指令速度，实际运动取决于舵机、负载与供电；中心死区也不等于保证的实际定位精度。角速度按20ms积分，主循环卡顿也不补做大跳。当前软件限位yaw60～210°、pitch60～120°，底座总计150°、相对正前左右各75°；底座两端对应PWM约944μs和2056μs。270°仍是舵机标定总行程。按用户要求从原105～165°扩大后，需在实物检查支架与线材无干涉。TRAVEL_DEG仍固定270/180，不随限位改变。

抖动时先降低KP或增大死区；跟随过慢再缓慢提高KP，但不超过已确认的机械速度。YOLO推理导致帧间隔经常超过300ms时，会按设计保持；先实测帧率，再决定降低推理延迟或适度增加超时（停机等待也会相应增加）。

## 7. 验证记录与限制

- 四阶段Arm Compiler6.7编译/链接通过，-Wall/-Wextra/-Werror；主机MSVC实际编译C解析器/控制器/应用并执行断言，覆盖边界坏帧、重同步、超时、计时回绕、死区、限速、双向限位、最新丢失帧优先、阶段3无PWM；K230发送函数的Python测试通过。
- 可重跑 `python tests/run_c_checks.py`（默认本机MSVC路径，可用C30D_VCVARS覆盖）及 `python tests/run_protocol_checks.py`。主机测试不能验证板级引脚电气、定时器实际波形或闭环稳定性。
- 没有连接实物执行烧录、负载供电或视觉闭环。本工程输出的是可烧录构建及分步上板验收方法；方向、机械零位与干涉范围必须按上述步骤在实物确认。

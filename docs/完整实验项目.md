# 二维云台跟踪射击：项目与部署顺序

本仓库将原实验目录和配套的 K230/C30D 项目放在一起，保留各自可运行的目录结构。目标为 K230 检测 sabo，按 UART 协议发送中心偏差，C30D 驱动二自由度云台跟随，并按当前固件的左右居中规则控制 PC12 继电器。

## 各部分职责

| 目录 | 职责 |
| --- | --- |
| `CanMV_V3.0/04_MicroPython例程源码/` | 原基础与视觉学习例程；其中 person_detection.py 已改为 sabo 跟踪 |
| `model/mp_deployment_source/` | sabo 模型和 JSON；按所选入口复制到对应 SD 卡路径 |
| `k230-stm32-tracking/outputs/person_detection.py` | 已适配 CSI0、IDE 预览、sabo 模型和 UART 发送的部署副本 |
| `k230-stm32-tracking/outputs/standalone/main.py` | 默认无预览的离线启动入口 |
| `wheeltec_c30d_pan_tilt/firmware/` | STM32F407 C30D 源码、Keil 工程、CMSIS 依赖和许可证 |
| `wheeltec_c30d_pan_tilt/tests/` | 已有 C 控制逻辑与协议主机检查 |
| `wheeltec_c30d_pan_tilt/outputs/` | 烧录文件、接线、分步验证和代码解释 |

## 当前接线及控制版本

以 C30D 项目的最新 README 和配置为准：K230 IO44 → C30D PA3（USART2_RX），GND 共地；PC6 / PC7 输出两路舵机 PWM。不要将旧 PD6 蓝牙接口方案与当前 PA3 固件混用。厂商 C06 资料不等于当前 C30D 硬件配置。

串口为 115200 8N1，协议为 `$T,found,ex,ey\n`，实际以 LF 结束。ex / ey 取 -1000～1000，右 / 下为正；没有目标发送 `$T,0,0,0\n`。接收超时为 300ms。

当前跟踪固件俯仰软件限位为 60°～120°；继电器仅要求左右误差 ex 在 ±50 内连续 2 秒，上下误差不参与居中点灯判定。当前参数来自原项目，实际运动范围及方向仍须按实物校准。

## 推荐部署顺序

1. 阅读 [供电与逐线连接说明](../wheeltec_c30d_pan_tilt/outputs/供电与逐线连接说明.md)。
2. 阅读 [编译烧录与分步验证](../wheeltec_c30d_pan_tilt/outputs/编译烧录与分步验证.md)，先验证舵机单项和 UART 接收。
3. 按 [sabo 模型部署说明](../k230-stm32-tracking/outputs/sabo模型部署说明.md) 准备 `/sdcard/model/mp_deployment_source/`，运行跟踪入口；它不同于原 `model/det_video.py` 的 Pipeline 入口。
4. 使用 C30D `04_tracking_PA3.hex` 做受控联调，确认转动使目标误差减小，再验证丢失和通信超时行为。
5. 需要开机自启时，按 [离线部署说明](../k230-stm32-tracking/outputs/standalone/离线部署说明.md) 将离线入口复制为 `/sdcard/main.py`。

## 编译与检查

从 `wheeltec_c30d_pan_tilt` 目录执行原有命令：

```powershell
python firmware/build_keil.py
python tests/run_c_checks.py
python tests/run_protocol_checks.py
```

编译依赖原脚本中配置的本地 Keil / ARM 工具链；C 检查依赖 MSVC，可通过 `C30D_VCVARS` 指定环境脚本。本仓库没有重新编译或烧录所有固件，随附 HEX 是复制的现有产物。

旧说明中的历史参数和“给另一个聊天”的表述作为原记录保留；当前参数冲突时，以最新 C30D README、实际源配置和本文的版本指引为先。部分历史说明引用的原厂参考图片/PDF、工作目录和外部源码备份未收录。

本次是资料与代码发布整理。主机检查及语法检查不能代替实机烧录、模型加载、摄像头帧率、云台闭环和供电验收。

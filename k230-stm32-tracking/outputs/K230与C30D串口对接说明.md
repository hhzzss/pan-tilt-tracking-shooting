## 串口配置与接线

K230：UART2，115200 波特率，8 数据位，无校验，1 停止位，无流控。

| K230 | C30D | 用途 |
| --- | --- | --- |
| IO44 / UART2_TXD | C30D 程序实际配置的 UART RX | K230 发送跟踪帧 |
| GND | GND | 共地 |
| IO45 / UART2_RXD | 当前无需连接 | 本程序不接收数据 |

IO44/IO45 是芯片 IO 编号，**不是排针第 44/45 脚**，请按 DshanPI CanMV V3 引脚图找对应位置。上述复用来自配套例程，尚未在实物上测量验证。C30D 不必选择 UART2，两端外设编号互不相关。

只连接匹配的 3.3V TTL 串口信号；不直接接 RS232 电平接口。舵机按 C30D/S20 文档供电，不从 K230 的 IO/3.3V 引脚取舵机电源。C30D 的实际 MCU、RX 引脚与舵机通道须由它的资料确认，不能套用旧 C06 板资料。

## 双方统一协议

ASCII 文本，每帧以 `$T,` 开头，以一个真正的换行字节 LF（0x0A）结尾：

```text
$T,found,ex,ey\n
```

文档中 `\n` 表示一个换行符，线上不会发送反斜杠和字母 n。C30D 接受 LF 或 CRLF，本程序发送 LF。没有额外空格，没有校验和。IDE 的 print 日志经 USB 显示，UART2 仅写入跟踪帧。K230 代码中的 dx、dy 分别对应协议的 ex、ey，线上只发送数值，因此无需改动 Python 变量名。

| 字段 | 含义 |
| --- | --- |
| found | 1：有目标；0：无目标 |
| ex（代码中 dx） | 横向归一化偏差，整数 -1000～1000；目标在画面右边为正 |
| ey（代码中 dy） | 纵向归一化偏差，整数 -1000～1000；目标在画面下边为正 |

**dx、dy 既不是像素值，也不是舵机角度。** 归一化公式为：

```text
cx = (x1 + x2) / 2
cy = (y1 + y2) / 2
dx = round((cx - W/2) / (W/2) * 1000)
dy = round((cy - H/2) / (H/2) * 1000)
```

使用后处理已经映射回采集图像的坐标，当前 W=640、H=480；不要用 640×640 模型输入尺寸再次计算误差。

| 情况 | 目标中心（640×480） | 实际发送内容（以换行结束） |
| --- | --- | --- |
| 目标居中 | (320, 240) | `$T,1,0,0` |
| 目标右上方 | (400, 180) | `$T,1,250,-250` |
| 目标左下方 | (240, 300) | `$T,1,-250,250` |
| 没有检测到目标 | 无 | `$T,0,0,0` |

正常持续检测时最多每 50ms 发送一次（约 20Hz 上限），实际帧率受推理速度限制；发现/丢失状态变化时立即发送，所以状态切换时允许短于 50ms 的间隔。没有目标时也持续发送无目标帧。初始化摄像头/模型期间不周期发送，C30D 此时按超时处理并保持姿态。

C30D 已确定默认接收超时为 **300ms**，正常跟踪时新的有效帧间隔必须小于 300ms，并应留出余量。50ms 是发送节流间隔，不能保证推理后实际达到 20Hz；需在 C30D 接收端实测完整有效帧的间隔。若采集/推理/显示持续耗时超过 300ms，会触发停止更新并保持姿态，应先优化处理耗时或双方重新确定超时。不要定时重发旧坐标来掩盖推理停顿。

## 给另一个聊天里的 C30D 开发约定

1. 根据 **C30D 实际型号、原理图及工程**选择 RX 和两个舵机的 PWM 通道，先独立验证底座、俯仰的中位、方向、脉宽与机械安全范围。硬件是 S20 系列，底座标称 270°、俯仰标称 180°；可用范围需实测。
2. UART 使用 115200、8N1，接收 `$T,found,ex,ey\n`，LF 或 CRLF 结束。按字节缓存直至 LF，处理分包和连续多帧；限制帧长（例如 64 字节），遇到新的 `$` 可重新同步起点。只接受字段完整、found 为 0/1、ex/ey 均在 -1000～1000 的有效帧。
3. 每个有效帧更新接收时间和最新目标状态；found=0 时立即清除旧误差。无效帧不能刷新有效数据接收时间。
4. 固定控制周期内，只有 found=1 且数据未超时才允许根据误差改变舵机目标角；found=0 或超时则保持当前位置。按已确定的默认 **300ms** 检测接收超时；超时后清除旧目标状态，恢复收到有效目标帧才继续跟踪。以下控制示意中的 dx/dy 指接收到的 ex/ey。
5. 先用 P 控制，横向和纵向分别调试。可按归一化误差计算角速度，再乘固定控制周期得到本次角度增量：

   ```text
   ex = dx / 1000.0
   ey = dy / 1000.0
   pan_speed  = direction_x * Kx * ex
   tilt_speed = direction_y * Ky * ey
   pan_angle  += limit_speed(pan_speed)  * dt_seconds
   tilt_angle += limit_speed(tilt_speed) * dt_seconds
   ```

   Kx/Ky 的单位是度/秒，direction_x/direction_y 由安装方向设为 +1 或 -1。目标在右边时，先小幅测试底座往哪个方向转能让 dx 的绝对值减小；目标在下边时同理测试俯仰。不要仅凭舵机角度增加方向猜测。
6. 每个轴增加中心死区（可从归一化偏差 ±30 开始，约横向 9.6 像素、纵向 7.2 像素）、速度限制和机械角度限位。死区内该轴角速度为 0，不反复微调。角度更新到达限位后钳位，不继续累积超出限位的目标值。
7. 摄像头必须随云台一起转动，才构成“检测偏差→转动→画面误差减小”的视觉反馈闭环。标称舵机总角度不等于整套云台的安全机械范围。

此协议已落实到 K230 代码。已在另一个项目找到 C30D 跟随固件：`../../wheeltec_c30d_pan_tilt\outputs\firmware\04_tracking_PA3.hex`，接收脚为 PA3。原来的单项测试已由用户确认成功，后续按本说明进行真实模型的闭环验证。

## 本次代码入口

在 `person_detection.py` 中搜索以下名称即可定位：

- `select_target`：筛选类别并选择最大目标框；越界坐标裁剪，退化框忽略。
- `target_error`：中心误差归一化。
- `send_tracking`：ASCII 帧打包和 UART 写入长度检查。
- `draw_result`：显示画面中心与选中目标。
- `uart_tx_pin`：串口引脚、波特率、发送间隔、目标类别配置。
- `stage = "target/UART"`：每帧推理后计算并按发送时机写出最新偏差。
- `finally`：退出时清除目标并释放 UART/摄像头/显示/模型资源。

多目标策略是“当前面积最大”，不保留同一目标的身份；多人同时出现且大小交替时可能切换目标。当前单目标实验无需引入完整目标跟踪算法。

## 实机检查顺序

1. 在 CanMV IDE 运行新 `person_detection.py`。启动应出现 `[OK] UART2 TX=IO44 RX=IO45 baud=115200`，随后出现原有摄像头、模型与首次推理日志。
2. 先观察预览：sabo 目标在右边时 dx>0，下边时 dy>0，靠近画面中心两轴接近 0；离开画面应显示 NO TARGET。
3. 在 C30D 上先只接收并检查解析值，暂不根据数据转动舵机；确认它接收到的是换行文本协议且字段含义一致。
4. 启用小速度控制，先单轴、后双轴，确认转动后对应偏差减小。再调死区、增益、限速与限位。
5. 检查目标离开、K230 停止运行、通信线断开后，C30D 不会继续使用旧偏差转动。

部署时把 Python 文件复制到开发板；要开机自启则保存为 `/sdcard/main.py`，模型路径仍需在 SD 卡上存在。修改 MicroPython 脚本不需要重新烧录 CanMV 固件。
